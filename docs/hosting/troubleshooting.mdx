## 查看日志

如果你通过 CLI 安装，请使用内置的日志命令：
```bash
inbox-zero logs            # 显示最后 100 行
inbox-zero logs -f         # 实时跟踪日志
inbox-zero logs -n 500     # 显示最后 500 行
```

如果你直接运行 Docker，请使用：
```bash
docker logs inbox-zero-services-web-1
docker logs inbox-zero-services-db-1
docker logs inbox-zero-services-redis-1
```

## 容器无法启动

使用上面的命令检查日志中的错误。

**常见问题：**
- **端口冲突**：另一个服务正在使用 3000、5432 或 6379 端口
  - 解决方案：启动前通过环境变量设置自定义端口：`WEB_PORT=3001 POSTGRES_PORT=5433 REDIS_PORT=6381 inbox-zero start`
- **需要从另一台机器远程访问 DB/Redis**：出于安全考虑，Postgres/Redis 端口默认绑定到 localhost
  - 解决方案：启动前设置 shell 环境变量，例如：`POSTGRES_BIND_HOST=0.0.0.0 REDIS_BIND_HOST=0.0.0.0 REDIS_HTTP_BIND_HOST=0.0.0.0 docker compose --profile all up -d`
- **内存不足**：容器被 OOM 终止
  - 解决方案：增加 VPS 内存或添加 swap 空间
- **缺少环境变量**：检查 `.env` 文件是否存在且包含必需的值
  - 解决方案：再次运行 `inbox-zero setup`
- **容器启动了但忽略了你的设置**：Compose 找不到你的 env 文件，于是在没有它的情况下启动。这通常发生在使用命名配置（例如 `.env.production`）或默认位置之外的文件，并用普通 `docker compose up` 启动时
  - 解决方案：使用 `inbox-zero setup` 打印出的 Compose 命令，或显式传入文件：`docker compose --env-file <path-to-your-env-file> --profile all up -d`。在 env 文件内设置 `INBOX_ZERO_ENV_FILE` 只有在该文件通过 `--env-file` 传入时才会生效
- **页面加载缓慢并出现 `validate-email-account` 或 `Unable to parse response body` Redis 警告**：`docker compose` 可能在缺少 `apps/web/.env` 中 token 的情况下启动了 `serverless-redis-http`
  - 解决方案：启动 Docker 前确保仓库根目录的 `.env` 与 `apps/web/.env` 一致，如果根目录没有 `.env` 就创建一个链接：`ln -s apps/web/.env .env`。保留并检查任何现有的根目录配置，然后用 `docker compose --env-file apps/web/.env --profile all up -d` 重建受影响的容器

## 数据库连接错误

**错误："Can't reach database server"**
- 等待 30-60 秒，让 Postgres 完全初始化
- 检查数据库容器正在运行：`docker ps | grep postgres`
- 验证 `.env` 中的 `DATABASE_URL` 与你的设置一致

**错误：P1000 / "authentication failed"**
- 当 `.env` 中的数据库密码与 Postgres Docker 卷中存储的密码不一致时会出现这种情况（例如，你先删除了 `.env` 而没有先删除卷，然后重新运行了 setup）。
- 修复：停止容器并删除卷，以便用当前密码重建 Postgres：
  ```bash
  docker compose --profile all down -v
  inbox-zero start
  ```

**错误："relation does not exist"**
- 迁移尚未运行
- 等待 web 容器完成启动（检查日志）
- 手动运行：`docker exec inbox-zero-services-web-1 npm run db:migrate`

## OAuth 配置问题

**错误："redirect_uri_mismatch"**
- 你的 OAuth 重定向 URI 与 Google/Microsoft 控制台中配置的不一致
- 确保在运行 `docker compose up` 时正确设置了 `NEXT_PUBLIC_BASE_URL`
- 将 `https://yourdomain.com/api/auth/callback/google` 添加到已授权的重定向 URI 中

**错误："invalid_client"**
- `GOOGLE_CLIENT_ID` 或 `GOOGLE_CLIENT_SECRET` 不正确
- 在 Google Cloud Console 中仔细核对凭据
- 确保 `.env` 文件中没有多余的空格或引号

## 无法访问应用

**无法通过域名访问：**
- 验证 DNS 记录指向你的 VPS IP：`dig yourdomain.com`
- 检查防火墙是否允许 3000 端口的流量：`sudo ufw status`
- 为 HTTPS 设置反向代理（Nginx/Caddy）

**可以通过 IP 访问但无法通过域名访问：**
- SSL/TLS 证书问题
- 使用 Caddy 搭配 Let's Encrypt 实现自动 HTTPS
- 或者用 Certbot 设置 Nginx

## 性能问题

**响应缓慢：**
- 检查 VPS 资源：`htop` 或 `docker stats`
- 如果持续高于 80%，请增加 VPS 内存
- 考虑使用外部托管数据库服务

**内存占用高：**
- 对 Next.js 应用来说是正常的（预计 500MB-1GB）
- 如果超过 1.5GB，请检查日志中是否有内存泄漏
- 重启容器：`docker compose restart web`

## AI 规则与邮件处理错误

**AI 驱动的规则失败，但手动创建的规则正常：**
- 这意味着你的 AI 服务商 API 密钥缺失、无效或额度用尽。
- 验证 `.env` 中已设置 `LLM_API_KEY`。
- 检查你的 API 密钥是否有计费额度。ChatGPT Plus 或 Claude Pro 订阅**不**包含 API 访问——你需要从服务商开发者平台获取一个带额度的独立 API 密钥。
- 你可以在应用的设置页面更改 AI 服务商。

**无法使用 AI 说明创建规则：**
- 原因相同——AI 服务商必须使用一个有效且有余额的 API 密钥正确配置。
- 检查日志（`inbox-zero logs -f`）以查看来自 AI 服务商的具体错误消息。

**邮件没有自动处理（Pub/Sub）：**
- 验证你的 Pub/Sub 主题和订阅配置正确——参见 [Pub/Sub 设置指南](/hosting/google-pubsub)。
- 推送订阅端点必须可以公开访问。本地开发时请使用 ngrok。
- 检查 `.env` 中已设置 `GOOGLE_PUBSUB_TOPIC_NAME` 和 `GOOGLE_PUBSUB_VERIFICATION_TOKEN`。
- 验证 Gmail 服务账号（`gmail-api-push@system.gserviceaccount.com`）在你的主题上具有 **Pub/Sub Publisher** 角色。

## 速率限制

**被邮件服务商限制速率（Gmail/Outlook）：**
- 如果你的邮箱账号同时连接了另一个正在发起请求的服务，就可能发生这种情况。
- 对于 Gmail：访问 https://myaccount.google.com/security 并查看 "Your connections to third-party apps & services"
- 对于 Outlook：访问 https://account.microsoft.com/privacy/app-access 查看已连接的应用

**被 AI 服务商限制速率：**
- 使用速率限制更高的其他 AI 模型。
- 升级到你 AI 服务商的更高层级。
- 降低发起请求的速率。

## 卸载 / 重新开始

### 快速重置

在不删除 Google Cloud 资源的情况下重新运行 setup：

**如果你使用 CLI（独立模式）：**
```bash
inbox-zero stop
docker compose -f ~/.inbox-zero/docker-compose.yml --profile all down -v
rm ~/.inbox-zero/.env
inbox-zero setup
```

**如果你从克隆的仓库运行：**
```bash
docker compose --profile all down -v
rm apps/web/.env
inbox-zero setup
```

### 完全移除

<Accordion title="移除所有内容，包括 Google Cloud 资源">

**1. 停止并移除容器和卷：**

如果你使用 CLI（独立模式）：
```bash
inbox-zero stop
docker compose -f ~/.inbox-zero/docker-compose.yml --profile all down -v
```

如果你从克隆的仓库运行：
```bash
docker compose --profile all down -v
```

**2. 移除本地配置：**

```bash
# 独立模式
rm -rf ~/.inbox-zero

# 如果从克隆的仓库运行
rm apps/web/.env
```

**3. 清理 Google Cloud 资源：**

1. **Pub/Sub：** 前往[订阅](https://console.cloud.google.com/cloudpubsub/subscription/list)并删除你的订阅，然后前往[主题](https://console.cloud.google.com/cloudpubsub/topic/list)并删除你的主题。
2. **OAuth 凭据：** 前往 [API 凭据](https://console.cloud.google.com/apis/credentials)并删除 OAuth 客户端。
3. **同意屏幕**（可选）：前往 [OAuth 同意屏幕](https://console.cloud.google.com/apis/credentials/consent)并重置或删除它。
4. **API**（可选）：前往[已启用的 API](https://console.cloud.google.com/apis/dashboard)，如果不再需要，请停用 Gmail、People、Calendar 和 Drive API。

</Accordion>
