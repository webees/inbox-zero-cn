---
title: 'Kubernetes 部署'
description: '使用 Helm chart 在 Kubernetes 上运行 Inbox Zero'
---

Inbox Zero 可以在 Kubernetes 上运行，使用与 Docker Compose 相同的组件：

- 用于 Next.js 应用的 `web` Deployment。
- 一个迁移 Job，在启用托管 Postgres 时于 Helm 安装或升级应用之前运行 Prisma 迁移。
- 一个用于持久后台任务的可选 BullMQ `worker` Deployment。
- 用于计划端点（如 watch 续订、会议简报、跟进提醒和保留清理）的 CronJobs。
- Postgres 和 Redis，可外部托管，也可安装在集群内以构成简单的自托管栈。
- 位于 Web Service 前面的 Ingress。

## Chart 位置

Chart 位于仓库中的：

```bash
charts/inbox-zero
```

使用以下命令安装：

```bash
helm upgrade --install inbox-zero ./charts/inbox-zero \
  -n inbox-zero \
  --create-namespace \
  -f values.prod.yaml
```

## Values 文件

Helm chart 不会取代常规的应用配置。完整的应用配置请参阅[环境变量参考](/hosting/environment-variables)、[Google OAuth 指南](/hosting/google-oauth)、[Microsoft OAuth 指南](/hosting/microsoft-oauth)和 [LLM 设置指南](/hosting/llm-setup)。

创建 `values.prod.yaml`，填入你的公开 URL、Ingress 设置和应用配置。将应用密钥放入 `secretEnv`，或让 chart 指向现有的 Kubernetes Secret。

```yaml
ingress:
  enabled: true
  className: nginx
  hosts:
    - host: app.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: inbox-zero-tls
      hosts:
        - app.example.com

env:
  NEXT_PUBLIC_BASE_URL: https://app.example.com
  GOOGLE_PUBSUB_TOPIC_NAME: projects/example/topics/inbox-zero
  QUEUE_BACKEND: bullmq

existingSecret: inbox-zero-secrets
```

`inbox-zero-secrets` 应包含[环境变量参考](/hosting/environment-variables)中列出的必需应用环境变量。对于简单安装，你也可以改用 `secretEnv`。

对于首次安装并附带内置 Postgres 和 Redis 的情况，还需要为这些内置服务提供生成的值：

```yaml
existingSecret: ""

postgresql:
  auth:
    password: replace-with-random-value

redis:
  auth:
    password: replace-with-random-value

redisHttp:
  token: replace-with-random-value
```

默认 chart 包含 Postgres、Redis、Redis HTTP 桥接、web、worker 和 CronJobs。这对首次 Kubernetes 安装很有用。生产环境请使用具备备份、故障转移、监控和经过测试的恢复的托管 Postgres 和 Redis。

## 推荐的生产设置

通过现有的 Kubernetes Secret 使用托管 Postgres 和 Redis：

```yaml
externalDatabase:
  enabled: true
  existingSecret:
    name: inbox-zero-database

externalRedis:
  enabled: true
  existingSecret:
    name: inbox-zero-redis
```

`inbox-zero-database` 应包含 `DATABASE_URL` 和 `DIRECT_URL`。

`inbox-zero-redis` 应包含 `REDIS_URL`、`REDIS_HTTP_URL` 和 `REDIS_HTTP_TOKEN`。仍使用 `UPSTASH_REDIS_URL` 和 `UPSTASH_REDIS_TOKEN` 的 Secret 可继续工作：将 `redisHttpUrlKey` 和 `redisHttpTokenKey` 留空，或将这些键指向遗留名称。

你可以使用普通 Kubernetes Secrets、External Secrets、Sealed Secrets、SOPS 或云密钥控制器。

应用密钥也请使用 `existingSecret`。完整列表（包括 OAuth、LLM、Redis 和 QStash 变量）请参阅[环境变量参考](/hosting/environment-variables)。

## 后台任务

BullMQ 是 Kubernetes 的默认队列模式：

```yaml
env:
  QUEUE_BACKEND: bullmq
worker:
  enabled: true
```

Worker 从 Redis 读取任务，并使用 `INTERNAL_API_KEY` 将任务转发到内部 Web Service。

要改用 QStash，请禁用 worker：

```yaml
env:
  QUEUE_BACKEND: qstash
worker:
  enabled: false
```

使用 `secretEnv` 或 `existingSecret` 提供 QStash 密钥；参见[环境变量参考](/hosting/environment-variables)。

## 冒烟测试

安装后，检查发布状态：

```bash
kubectl get pods -n inbox-zero
kubectl rollout status deploy/inbox-zero-web -n inbox-zero
```

测试健康检查端点：

```bash
kubectl port-forward svc/inbox-zero-web 3000:80 -n inbox-zero
curl http://localhost:3000/api/health
```

测试一个计划任务：

```bash
kubectl create job --from=cronjob/inbox-zero-watch-renewal test-watch-renewal -n inbox-zero
kubectl logs job/test-watch-renewal -n inbox-zero
```

## 运维说明

- 将 `NEXT_PUBLIC_BASE_URL` 设置为用户和 OAuth 提供方使用的外部 HTTPS URL。
- 使用托管 Postgres 时，Helm 会在 pre-install/pre-upgrade Job 中运行 Prisma 迁移。
- 启用迁移 Job 时，Web Pod 会设置 `SKIP_DB_MIGRATIONS=true`。
- 使用内置 Postgres 时，Web 容器会在启动期间运行迁移。
- 内置 Postgres、Redis 和 Redis HTTP 需要显式密钥值。请在安装前生成它们，例如使用 `openssl rand -hex 32`。
- CronJobs 调用内部 Service，而不是公共 Ingress。
- Cron 计划在 `cron.jobs` 下配置。默认值遵循 Docker 自托管设置，因此某些计划与托管部署的计划不同。
- `/api/health` 端点支持无需 API 密钥的轻量级 Kubernetes 探针。
