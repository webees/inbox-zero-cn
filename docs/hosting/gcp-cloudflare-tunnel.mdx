本指南介绍如何在 GCP Compute Engine VM 上通过 Cloudflare Tunnel 部署 Inbox Zero，以安全地通过 HTTPS 访问。Cloudflare Tunnel 免去了反向代理（Nginx/Caddy）和 SSL 证书管理——隧道从你的 VM 向外连接到 Cloudflare 边缘，因此无需开放任何入站防火墙端口。

**为什么选择 Cloudflare Tunnel？**
- 无需 Nginx、Caddy 或 Let's Encrypt 设置即可使用 HTTPS
- 无需公开入站端口——VM 仅发起出站连接
- 在 Cloudflare 免费套餐上免费使用
- 与运行集成 Gmail 应用的 GCP VM 天然契合（同一 Google Cloud 项目）

## 前置条件

- 已启用计费的 [Google Cloud](https://console.cloud.google.com) 账号
- 拥有由 Cloudflare DNS 管理域名的 [Cloudflare](https://cloudflare.com) 账号（免费套餐）
- 对 GCP 的 SSH 访问（通过 `gcloud` CLI 或基于浏览器的 SSH）

## 1. 创建 Compute Engine VM

1. 转到 **Compute Engine → VM instances → Create instance**
2. **Name：** `inbox-zero`（或你选择的名称）
3. **Region/Zone：** 选择靠近你用户的区域
4. **Machine configuration：**
   - 最低配置：`e2-medium`（2 vCPU，4 GB RAM）——使用此规格时请添加 swap
   - 推荐配置：`e2-standard-2`（2 vCPU，8 GB RAM）
5. **Boot disk：**
   - 操作系统：**Debian 12** 或 **Ubuntu 24.04 LTS**
   - 大小：至少 **20 GB**（Docker 镜像 + 日志）
6. **Firewall：** 保持 HTTP 和 HTTPS 复选框**未勾选**——Cloudflare Tunnel 处理所有入站流量
7. 点击 **Create**

### 可选：预留静态外部 IP

VM 停止后 GCP 外部 IP 会发生变化。如果你需要从固定地址进行 SSH 访问，请在 **VPC network → IP addresses** 下预留静态 IP 并将其附加到 VM。Cloudflare Tunnel 不需要静态 IP。

## 2. 安装 Docker 和 Docker Compose

通过 SSH 登录 VM 并运行：

```bash
# Update packages
sudo apt-get update && sudo apt-get upgrade -y

# Install Docker Engine
curl -fsSL https://get.docker.com | sudo sh

# Allow your user to run docker without sudo
sudo usermod -aG docker $USER
newgrp docker

# Verify
docker --version
docker compose version
```

### 添加 swap（e2-medium 必需）

如果你使用 `e2-medium`（4 GB RAM），请添加 swap 以避免 OOM 终止：

```bash
sudo dd if=/dev/zero of=/swapfile bs=128M count=32
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab
```

## 3. 设置 Cloudflare Tunnel

### 创建隧道

在 **Cloudflare 仪表板**中：

1. 转到 **Zero Trust → Networks → Tunnels → Add a tunnel**
2. 选择 **Cloudflared** 作为连接器类型
3. 为隧道命名（例如 `inbox-zero`）
4. 按照 **Debian** 的安装说明操作——复制仪表板中显示的 `cloudflared` 安装命令并在你的 VM 上运行：

```bash
# Example — copy the exact command from the Cloudflare dashboard
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
```

5. 运行仪表板中显示的服务安装命令。它看起来像这样：

```bash
sudo cloudflared service install <YOUR_TUNNEL_TOKEN>
```

这会将 `cloudflared` 注册为开机自动启动的 `systemd` 服务。

### 配置公共主机名

回到 Cloudflare 仪表板的隧道设置：

1. 转到 **Public Hostnames** 标签页
2. 点击 **Add a public hostname**
3. **Subdomain：** 例如 `inbox`（结果为 `inbox.yourdomain.com`）
4. **Domain：** 你由 Cloudflare 管理的域名
5. **Service：** `http://localhost:3000`
6. 保存——Cloudflare 会自动添加一条 CNAME DNS 记录

隧道运行且应用启动后，你的应用可通过 `https://inbox.yourdomain.com` 访问。

## 4. 设置 Inbox Zero

### 选项 A：CLI（推荐）

```bash
# Install Node.js (required for the setup CLI)
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt-get install -y nodejs

# Run the setup wizard
npx @inbox-zero/cli setup
```

出现提示时，输入完整的 Cloudflare Tunnel URL 作为基础 URL（例如 `https://inbox.yourdomain.com`）。

### 选项 B：手动

```bash
git clone https://github.com/elie222/inbox-zero.git
cd inbox-zero
cp apps/web/.env.example apps/web/.env
nano apps/web/.env
```

需要设置的关键变量：

```env
# Your Cloudflare Tunnel public hostname
NEXT_PUBLIC_BASE_URL=https://inbox.yourdomain.com

# Google OAuth
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...

# LLM provider/model
DEFAULT_LLMS=anthropic:claude-sonnet-4-5-20250929
ANTHROPIC_API_KEY=...
```

完整列表请参阅[环境变量参考](/hosting/environment-variables)。

## 5. 启动应用

```bash
NEXT_PUBLIC_BASE_URL=https://inbox.yourdomain.com docker compose --profile all up -d
```

检查所有容器是否已启动：

```bash
docker ps
docker logs inbox-zero-services-web-1 -f
```

启动需要 30–60 秒。当 Web 容器日志显示 Next.js 服务器已就绪后，访问你的 Cloudflare URL。

## 6. 更新 Google OAuth 重定向 URI

在 [Google Cloud Console → APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials) 中打开你的 OAuth 客户端并添加：

```
https://inbox.yourdomain.com/api/auth/callback/google
```

到 **Authorized redirect URIs** 列表。

## 维护

### VM 重启后重新启动

Docker（使用 `--restart unless-stopped` / Compose）和 `cloudflared` 都作为 systemd 服务运行，并会自动重启。使用以下命令验证：

```bash
systemctl status cloudflared
docker ps
```

### 更新到最新镜像

```bash
docker compose pull
NEXT_PUBLIC_BASE_URL=https://inbox.yourdomain.com docker compose --profile all up -d
```

### 查看日志

```bash
docker logs inbox-zero-services-web-1 -f
journalctl -u cloudflared -f
```

## 故障排查

**隧道显示为“Healthy”但站点返回 502：**
- 应用容器可能仍在启动——等待 60 秒后刷新
- 检查 `docker logs inbox-zero-services-web-1` 中的启动错误

**Cloudflare Tunnel 已断开：**
- 检查 `journalctl -u cloudflared` 中的错误
- 验证 VM 具有出站互联网访问（在 GCP 上默认应可用）

**Google OAuth redirect_uri_mismatch：**
- 确保 `NEXT_PUBLIC_BASE_URL` 与 Google Cloud Console 中注册的重定向 URI 完全一致
- 必须与 Cloudflare 主机名匹配，包括 `https://`

其他问题请参阅[故障排查指南](/hosting/troubleshooting)。
