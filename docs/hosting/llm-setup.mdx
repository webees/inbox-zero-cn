对于自托管，请在 `apps/web/.env` 中通过环境变量配置 AI。
如果你使用了 `inbox-zero setup`，其中许多值会自动配置。

从这里开始：

- [环境变量](/hosting/environment-variables)（完整参考）

<Warning>
  API 密钥需要在提供方平台上拥有计费额度。ChatGPT Plus 或 Claude Pro 订阅**不**包含 API 访问权限。
</Warning>

## 层级

对于大多数自托管设置，配置默认层级，并可选覆盖更便宜或特定角色的层级：

- `DEFAULT_LLMS`（必需）：常规 AI 任务。
- `ECONOMY_LLMS`（可选）：用于高吞吐量任务的低成本模型。未设置时回退到默认值。
- `CHAT_LLMS`（可选）：助手聊天。未设置时回退到默认值。
- `DRAFT_LLMS`（可选）：回复起草。未设置时回退到默认值。
- `NANO_LLMS`（可选）：轻量分类和提取。未设置时回退到经济型/默认行为。

每个值都是按 `provider:model` 格式排列的逗号分隔有序列表。第一个有效条目是主模型。后续有效条目是按顺序排列的回退模型。模型名称可以包含冒号；只有第一个冒号用于分隔提供方和模型。

最小示例：

```env
DEFAULT_LLMS=openai:gpt-6-luna
ECONOMY_LLMS=openai:gpt-6-luna
LLM_API_KEY=sk-...
```

提供方专属密钥（例如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）同样可用。完整列表请参阅[环境变量](/hosting/environment-variables)。

## 应用设置

应用还提供 **Settings → AI**，用于设置每用户的密钥/模型，但自托管部署通常将配置保持在环境变量层面。

## 敏感数据保护

自托管部署可以选择 LLM 请求在发送给 AI 提供方之前如何处理敏感数据匹配。当前扫描器针对可能的凭据/令牌和类似支付卡号的数字；它不是完整的 DLP 或 PHI 分类器。

```env
SENSITIVE_DATA_POLICY_DEFAULT=ALLOW # ALLOW, REDACT, or BLOCK
NEXT_PUBLIC_SENSITIVE_DATA_POLICY_LOCKED=false
```

`ALLOW` 保持默认行为。`REDACT` 会在 LLM 请求之前替换匹配的值。`BLOCK` 会在发现匹配时停止请求。保持 `NEXT_PUBLIC_SENSITIVE_DATA_POLICY_LOCKED=false` 可让用户在设置中按账号选择，或将其设为 `true` 以对所有账号强制执行部署默认值，并在 UI 中隐藏该设置。

## 决策模型

某些分类步骤（规则选择、发件人分类、会话状态、重复模式检测、回复记忆选择以及退订页面检查）可以使用决策模型而不是 LLM。冷邮件检测使用 LLM，除非 `DECISION_MODEL_COLD_EMAIL_ENABLED=true`。决策模型针对结构化状态回答类型化问题，并返回经过校准的概率。它们通过 AI SDK 的决策模型接口运行，因此切换模型只是配置变更：

```env
DEFAULT_DECISION_MODEL=openrouter:typesafe/jev-1.13 # or openrouter:cloudflare/clef
DEFAULT_DECISION_MODEL_ENABLED=false # true: on for users who haven't chosen; false: users opt in
DECISION_MODEL_COLD_EMAIL_ENABLED=false # true: the decision model also detects cold email
```

使用与 `*_LLMS` 变量相同的 `provider:model` 格式。支持的提供方为 `openrouter`、`aigateway`、`openai` 和 `typesafe`。密钥解析方式也相同：使用提供方的密钥（`OPENROUTER_API_KEY`、`AI_GATEWAY_API_KEY` 或 `OPENAI_API_KEY`），回退到 `LLM_API_KEY`。直接使用 TypeSafe 始终需要 `TYPESAFE_API_KEY`。

决策模型接收与它所替代的 LLM 相同的电子邮件内容，并应用相同的敏感数据策略。自行设置 AI 密钥的用户默认不会被纳入。如果决策调用失败，该步骤会回退到已配置的 LLM。

### 启用

1. 设置 `DEFAULT_DECISION_MODEL` 和提供方的 API 密钥，然后重启。例如，通过 OpenRouter 使用 Jev：`DEFAULT_DECISION_MODEL=openrouter:typesafe/jev-1.13` 配合 `OPENROUTER_API_KEY`。对于 Clef，请使用 `openrouter:cloudflare/clef`。
2. 每个用户随后会在 **Settings → AI Model** 下看到 **Specialized decision model** 开关。在用户开启之前，它处于关闭状态。
3. 要为所有尚未选择的用户开启，请设置 `DEFAULT_DECISION_MODEL_ENABLED=true`。这不包括使用自己 AI 密钥的用户，用户在设置中的选择始终优先。

如果 `NEXT_PUBLIC_AI_MODEL_SETTINGS_DISABLED=true`，该开关会被隐藏。此时由 `DEFAULT_DECISION_MODEL_ENABLED` 为尚未选择的用户决定。

## 提供方专属细节

- `azure-foundry` 需要 `AZURE_FOUNDRY_API_KEY` 和 `AZURE_FOUNDRY_BASE_URL`。使用部署名称作为 `azure-foundry:<deployment>` 条目中的模型部分。
- `cerebras` 使用 `CEREBRAS_API_KEY`（或 `LLM_API_KEY`）访问 `https://api.cerebras.ai/v1`。示例聊天模型：`CHAT_LLMS=cerebras:qwen-3.8-27b`。
- `openai-compatible` 还需要 `OPENAI_COMPATIBLE_BASE_URL`。当服务器期望 `api-key` 请求头而不是 bearer 授权时，设置 `OPENAI_COMPATIBLE_AUTH_HEADER=api-key`。如果你不想使用专用提供方，这可以指向 Cerebras（`https://api.cerebras.ai/v1`），但此时你无法同时使用本地 OpenAI 兼容服务器。
- `ollama` 可以使用 `OLLAMA_BASE_URL` 和 `OLLAMA_MODEL`。

## 回退

通过向同一角色列表添加更多条目来添加回退：

```env
DEFAULT_LLMS=openrouter:anthropic/claude-sonnet-5,openai:gpt-6-luna
ECONOMY_LLMS=openrouter:openai/gpt-6-luna,google:gemini-3.1-flash-lite
CHAT_LLMS=openrouter:anthropic/claude-haiku-4.5,openai:gpt-6-luna
```

不受支持的提供方、未配置凭据的条目、没有模型的条目以及重复项会被跳过并给出警告。

### 遗留变量

旧的 `DEFAULT_LLM_PROVIDER` / `DEFAULT_LLM_MODEL`、特定角色的 `*_LLM_PROVIDER` / `*_LLM_MODEL` 以及 `*_LLM_FALLBACKS` 变量已弃用，但现有部署仍受支持。启动时，它们会被转换为对应的 `*_LLMS` 值。新部署和 CLI 生成的环境文件应使用 `*_LLMS`。

### CLI LLM 提供方

`codex-cli` 和 `claude-code` 是实验性的自托管选项。它们使用
会启动本地 CLI 工具的第三方社区 AI SDK 提供方包，因此
除非 `CLI_LLM_ENABLED=true`，否则处于禁用状态。

仅在可信的自托管部署中使用它们。审查提供方包的
源代码、固定精确的包版本，并确保你的认证方式符合相关的
OpenAI 或 Anthropic 条款。

Codex 示例：

```bash
cd apps/web
pnpm add ai-sdk-provider-codex-cli@1.1.0
pnpm add -g @openai/codex
codex login
```

```env
CLI_LLM_ENABLED=true
DEFAULT_LLMS=codex-cli:gpt-5.3-codex
CODEX_CLI_ALLOW_NPX=false
```

Claude Code 示例：

```bash
cd apps/web
pnpm add ai-sdk-provider-claude-code@4.3.1
claude auth login
```

```env
CLI_LLM_ENABLED=true
DEFAULT_LLMS=claude-code:sonnet
```
