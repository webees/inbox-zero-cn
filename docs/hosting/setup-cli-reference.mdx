自托管设置 CLI 不同于公开的 [API CLI](/api-reference/cli)。它创建部署配置并可引导提供方设置；它不会通过公开 API 管理现有收件箱。

## 启动向导

使用以下命令运行最新设置向导：

```bash
npx @inbox-zero/cli@latest setup
```

交互式向导会询问你要配置哪种部署目标和提供方。在提交或部署生成的文件之前请先审查它们，因为它们可能包含特定环境的值。

## 设置命令

CLI 包含以下专用流程：

- 本地或基于 Docker 的设置
- Google OAuth、所需 API 和 Gmail Pub/Sub
- AWS 部署
- Terraform 生成与部署
- Vercel 部署

使用 `--help` 运行 CLI，或在某个命令后加 `--help`，以查看已安装版本支持的标志：

```bash
npx @inbox-zero/cli@latest --help
npx @inbox-zero/cli@latest setup-google --help
npx @inbox-zero/cli@latest setup-aws --help
npx @inbox-zero/cli@latest setup-terraform --help
npx @inbox-zero/cli@latest setup-vercel --help
```

## 自动化指南

首次部署推荐使用交互式设置。对于可重复的环境：

1. 在一次性或暂存工作区中运行向导。
2. 审查生成的配置并识别密钥。
3. 将密钥移入部署的密钥管理器。
4. 仅提交安全的模板和基础设施文件。
5. 以生成的输出作为常规部署流水线的基础。

绝不要将 OAuth 客户端密钥、数据库凭据、加密密钥或 AI 提供方密钥放入源代码管理。
