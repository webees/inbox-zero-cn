使用 Inbox Zero API 以编程方式读取收件箱统计、管理自动化规则并退订发件人。

如果你更想要用于脚本或机器人的 CLI 封装，请参阅 [API CLI](/api-reference/cli)。若要通过 OAuth 把 Cursor 或 Claude Code 连接到你的邮箱，请参阅 [MCP 服务器](/api-reference/mcp)。

## 支持的邮件服务商

Inbox Zero 支持与以下服务集成：
- **Gmail**（Google Workspace 和个人账号）
- **Outlook**（Microsoft 365 和个人账号）

## 开始使用

要开始使用 Inbox Zero API，你需要获取一个 API 密钥。方法如下：

1. 登录你的 Inbox Zero 账号
2. 导航到[设置](https://www.getinboxzero.com/settings)页面，向下滚动到 `API Keys` 部分
3. 点击 `Create New Secret Key` 按钮
4. 选择你的密钥所需的权限（作用域）
5. 选择一个有效期

<img src="/images/settings-api-key.png" alt="创建新的密钥" />

API 密钥限定于某个特定的收件箱账号，并且只授予你选择的权限。请妥善保管你的密钥，不要公开分享。

### 权限

| 作用域 | 端点 |
|---|---|
| `STATS_READ` | `GET /stats/by-period`、`GET /stats/response-time` |
| `RULES_READ` | `GET /rules`、`GET /rules/{id}` |
| `RULES_WRITE` | `POST /rules`、`PUT /rules/{id}`、`DELETE /rules/{id}` |
| `SENDERS_UNSUBSCRIBE` | `POST /senders/unsubscribe` |

一个密钥可以包含多个作用域。密钥也绑定到一个收件箱账号；它们无法读取或更改另一个收件箱。

### 自托管

如果你自托管 Inbox Zero，请在重新构建应用前设置 `NEXT_PUBLIC_EXTERNAL_API_ENABLED=true` 和 `API_KEY_SALT`。用 `openssl rand -hex 32` 生成该 salt。把你的部署 URL 用作请求的基础 URL（例如 `https://your-domain.com/api/v1`）。

## 基础 URL

所有 API 请求都应发送到以下基础 URL：

```
https://www.getinboxzero.com/api/v1
```

## 认证

在每个请求的头中包含你的 API 密钥：

```
API-Key: YOUR_API_KEY
```

例如，列出规则：

```bash
curl "https://www.getinboxzero.com/api/v1/rules" \
  -H "API-Key: YOUR_API_KEY"
```

退订某位发件人，使用与上面相同的 `API-Key` 头：

```bash
curl -X POST "https://www.getinboxzero.com/api/v1/senders/unsubscribe" \
  -H "API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{ "senderEmail": "news@example.com" }'
```

创建一条规则：

```bash
curl -X POST "https://www.getinboxzero.com/api/v1/rules" \
  -H "API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "name": "Archive newsletters",
    "runOnThreads": true,
    "condition": {
      "aiInstructions": "Newsletters and recurring promotional emails"
    },
    "actions": [{ "type": "ARCHIVE" }]
  }'
```

### 错误

API 错误以结构化 JSON 返回：

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing API key",
    "hint": "Include a valid API-Key header. See https://docs.getinboxzero.com/api-reference/introduction."
  }
}
```

| 状态码 | 代码 | 含义 |
|---|---|---|
| `400` | `BAD_REQUEST` | 查询、路径或请求体无效；某操作也可能因部署的功能开关而被禁用 |
| `401` | `UNAUTHORIZED` | `API-Key` 头缺失、无效或已过期 |
| `403` | `FORBIDDEN` | 密钥缺少必需的作用域，或不是账号范围内的 |
| `404` | `NOT_FOUND` | 所请求的路由或规则不存在 |
| `405` | `METHOD_NOT_ALLOWED` | 路由存在，但不支持所请求的 HTTP 方法 |
| `429` | `RATE_LIMITED` | 被 API 或邮件服务商限流 |
| `500` | `INTERNAL_ERROR` | 发生了意外的服务器错误 |

OpenAPI schema 发布在 [https://www.getinboxzero.com/openapi.json](https://www.getinboxzero.com/openapi.json)（也可在 `/api/v1/openapi` 和 `/.well-known/openapi.json` 获取）。

`DELETE` 规则操作会把匹配的邮件移动到回收站，仅在部署启用 `NEXT_PUBLIC_DELETE_EMAIL_ACTION_ENABLED` 时可用。此功能开关与 `DELETE /rules/{id}`（删除规则定义）不同。
